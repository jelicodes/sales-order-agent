# Domain Docs

Layout: single-context

## Structure

- `CONTEXT.md` at repo root — project overview, tech stack, conventions
- `docs/adr/` at repo root — Architecture Decision Records

## Consumer rules

- Read `CONTEXT.md` before making changes to understand project context
- Read relevant ADRs before overriding past decisions
- Create new ADRs in `docs/adr/` when making significant architectural choices
